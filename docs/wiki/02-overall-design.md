# 02. FlowForge 的整体设计：从有效结论到可验证交付

> 状态：重组后的结构稿，正文待完善。

## 概要

说明 FlowForge 如何组合 Skill、Markdown 工件和 CLI，把多轮分析、设计、任务准备、执行和反馈连接起来。先给出完整的信息流，再解释各部分职责，为后面的功能细节建立地图。

## 正文规划

### 1. 核心问题与总体思路

简要引用背景篇，说明持续维护有效结论、提前准备局部上下文、显式计算依赖和用证据交接的总体方案；不重新解释 Context 原理。

### 2. 一项需求如何贯穿整个过程

用一张流程图说明讨论与来源材料如何形成 Requirement、Design、Ticket 和 Evidence，以及发现缺口时返回谁处理。

### 3. Skill、Markdown 与 CLI 为什么这样分工

Skill 指导语义活动，文件保存内容，CLI 检查声明与计算关系；区分流程约定、程序检查和宿主权限保护。

### 4. 全局依据与局部工作如何连接

介绍正文、来源链接、元数据的不同作用，以及简单工作合在一张任务中、复杂工作拆出独立依据的原则。

### 5. 适用条件、代价与边界

说明准备和维护成本、人参与确认的必要性，以及图与格式检查不等于语义正确；不把预期收益当成实测结果。

## 内容边界

本文只讲全景及责任分工；字段、角色配置、修复规则在对应功能篇展开。
