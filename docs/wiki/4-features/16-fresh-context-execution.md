# 16. 新上下文与角色协作：从工件恢复一次有界工作

> 状态：结构稿，正文待完善。

## 概要

回答如何避免主会话不断承载所有阅读、执行与失败历史。解释一票一个执行上下文、角色分工、调度输入与结果交接，及哪些决定应由主会话保留。

## 正文规划

- 问题：历史负担累积，职责混合，交接输入不明确。
- 机制：以任务、关联依据和结果证据构造执行上下文。
- 区分工作分派、独立执行与安全并行。
- 边界：新上下文有准备与恢复成本，子代理不会天然共享全部工作状态。

## 例子与依据准备

核对项目执行单元策略与角色定义，不预设新上下文一定更快或更准确。
