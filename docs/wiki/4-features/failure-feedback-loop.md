# 19. 失败反馈：把一次执行的发现留给下一次

## 概要

回答如何避免失败原因只留在旧会话，以及任务事实错误如何被修正。解释 Blocked evidence、修订执行契约、Fix 变更与 repair ticket 的适用关系。

## 正文规划

- 问题：反复尝试、重复调查，执行者被迫自行改变设计。
- 机制：保存逐字错误与尝试，复核后更新契约或交回决定所有者。
- 区分局部修复、实质修复和需求/设计变更。
- 边界：失败史提供依据，不能保证不再失败；正式正文核对状态与依赖更新规则。
