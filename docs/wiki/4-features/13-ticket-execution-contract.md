# 13. 任务执行契约：把全局信息组织为局部工作依据

> 状态：结构稿，正文待完善。

## 概要

回答执行者如何知道交付什么、在哪里修改、遵守哪些边界以及怎样证明完成。解释三层 Ticket 和执行细化的分工，强调生成骨架与具备执行信息之间的差别。

## 正文规划

- 问题：任务存在，但执行仍依赖临时搜索和补决策。
- 机制：交付、局部设计、触点、变更、约束、验证与经核实的执行细节。
- 开工检查如何暴露缺项，细化如何处理仓库事实。
- 边界：任务为主要入口与绝对只读一份文件的区别；上游及代码读取按当前约定说明。
