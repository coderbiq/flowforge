# 07. 验证与反馈：证明交付、记录失败并收敛修复

> 状态：重组后的结构稿，正文待完善。

## 概要

围绕“如何知道做对了，出错后怎样继续”，解释验证、双轴审查、完成证据与失败反馈构成的闭环，并把前端视觉检查作为需要不同观察证据的具体场景。

## 正文规划

### 1. 从执行汇报到可检查证据

区分计划、实现记录、命令结果和 Completion evidence；检查退出状态、输出、产物与实现引用，说明勾选不能证明交付。

### 2. Standards 与 Specification 两轴审查

说明固定变更范围、有效依据、发现处置与关闭条件，避免同一不完整任务成为唯一验收依据。

### 3. 失败如何成为下一次工作的输入

说明 Blocked evidence、已试命令、错误事实与假设的区别，如何更新执行契约或返回需求设计责任方。

### 4. 修复如何进入后续执行

区分 Fix、repair ticket 与设计返回，说明状态、依赖和证据如何协调；重新计算队列指向第05篇。

### 5. 前端为什么还需要视觉证据

解释运行截图、条款对照、视觉自审与独立复核，区分量化检查和主观判断，并保留覆盖范围限制。

## 内容边界

本文负责结果和纠错闭环；规范如何准备见第04篇，执行身份及宿主约束见第06篇。

## 依据准备

核对 Implement/Review、前端相关 Skill、完成与阻断证据检查及修复流程。
