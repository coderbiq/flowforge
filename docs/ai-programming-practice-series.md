# AI 编程实战：从“能生成代码”到“能交付软件”

过去两年，我持续在实际开发中使用 AI，逐渐发现：让 AI 写出一段代码，和让它参与完成一个真实项目，是两件差别很大的事。需求理解偏了，代码可能写得越快，返工越多；设计看起来完整，落到实现时却可能遗漏关键约束；测试通过了，也不一定说明功能符合预期。随着任务变复杂、协作轮次变多，如何保留上下文、控制改动范围、验证交付结果，也会成为新的问题。

这个系列分享将围绕我最近两年使用 AI 编码的实际经验展开，以持续开发中的真实项目为案例，讨论 AI 在需求分析、方案设计、代码实现和 Code Review 中容易遇到的问题，以及我如何在实践中逐步调整协作方式。每次分享从一个具体问题切入，讲清楚当时的开发场景、AI 的表现、问题产生的原因、尝试过的解决办法，以及这些办法的适用条件和局限。

## 主要分享内容

### 需求分析：如何避免 AI 很快完成了一个错误的任务

当需求只是一个模糊想法，或者输入是一份混有旧结论的文档时，AI 很容易自行补全缺失信息，把推测当成事实。分享如何区分已知事实、待确认问题和实现建议，如何让 AI 先调查代码与现有行为，以及人应该在哪些关键问题上作出判断，减少“做完才发现理解错了”的返工。

### 方案设计：如何判断一个看似合理的方案是否真的可行

AI 能快速产出结构完整的设计，但完整的文字不代表合理的模块边界、接口和执行顺序。分享如何结合现有代码检查设计，追问责任归属、数据流、异常路径和验证方式，以及如何保留已经确认的决策，让后续实现能够沿着同一套设计推进。

### 代码实现：如何让 AI 持续完成可验证的改动

任务太大、上下文过长、约束传递不完整，都可能导致 AI 漏做、越界修改，或者在失败命令上反复打转。分享如何把工作拆成可独立验证的增量，明确输入、边界和完成条件，用测试与执行证据确认结果，并把失败原因留下来，让下一轮工作能够接着推进。

### Code Review：如何检查 AI 到底有没有把事情做好

代码风格符合规范、测试全部通过，仍然可能遗漏需求或边界场景。分享如何分别检查“是否符合工程规范”和“是否实现预期行为”，如何让审查结论对应到具体代码与证据，以及如何推动问题修复和复核，避免 Review 停留在一份看起来很全面的意见清单上。

### 持续协作：如何管理上下文、多个 Agent 与模型成本

当开发跨越多个会话，或需要多个 Agent 协作时，信息丢失、职责重叠和重复调查会逐渐影响效率。分享如何组织可交接的上下文、划分调查与决策、安排能够并行的任务，以及如何根据任务特点选择模型，在质量、时间和成本之间作出取舍。

## 希望带来的收获

这个系列面向已经开始使用 AI 编码、希望把它更稳定地用到实际项目中的开发者。希望大家带走的是一套判断和处理问题的方法：知道什么事情可以交给 AI，什么决策仍然需要自己负责，如何发现偏差，以及凭什么确认一次改动已经完成。

分享以真实问题、具体案例和实践中的调整为主。案例中的工具与流程会作为解决问题的背景出现，重点始终是开发者如何与 AI 协作，以及这些经验如何迁移到自己的项目中。
