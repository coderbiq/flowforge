## Evidence

### Observations

1. 可由仓库直接确认的 FlowForge 自身 artifacts：03-proposal/*.md 是 Proposal 索引；Proposal workspace 的 PROP/FEATURE/FIND/REQ/STR 与 JOURNAL.md 是 FlowForge 协作/控制面；01-workspace/03-completed/CR26062101、CR26062102 是已归档的 FlowForge Proposal；02-library 是 FlowForge archived knowledge。目录名和卡片 frontmatter 均支持这是 FlowForge 产生的历史 artifact，而非可自动删除的垃圾。
2. 历史 wiki/旧模型输入面：01-workspace/{01-active,03-completed} 可见 REQ-*、DES-*、TASK-*、LOG-*、STR-*；CR26062102 的卡片 frontmatter 仍是旧 type（例如 .../90-cards/DES-CR26062102-dji543o8ff5s_...md:2-5）。这些文件的旧 ID、文件路径、body 和 links 是历史事实源；validator 报错也来自其中的旧目标。
3. “用户历史 wiki”所有权不能仅凭 ff-wiki-flowforge 目录名或 active/completed/library 推断。现有证据只能确认它们位于 FlowForge wiki 数据集，不能证明某一文件属于外部用户；故外部用户归属、保留期限、在线展示/搜索需求均为 unknown，不得在本轮代替用户裁决。
4. 25 条断链是已有历史基线，不是本 Proposal 新增缺陷：validator 报错集中于 CR26062102 已完成目录的 PROP-CR26062102_*、DES-*、LOG-*、TASK-* 旧 targets，以及 library 的 CONV-djdorf97z66p、FIND-djdoa1ftfow2、STR-djdocjmfl2g0 旧链接/wikilink/缺失目标；不得通过改名、补 alias、重写链接或删除文件来“清零”。

### Inferences

- 当前面只能按 v3 source/domain（本 Proposal 的 PROP/FEATURE/FIND/REQ 和当前状态）验收；历史面必须作为独立只读集合。普通 CardStore、普通索引或 fallback 不得把历史集合重新混入 current tree/search。
- STR-<proposal>-REQ 不属于可随意归档/忽略的普通历史卡：accepted DEC 将其定义为 FlowForge Proposal control-plane metadata；保留原文件、旧 ID、links、body，普通 CardStore/index 排除，Proposal inspect/traceability 独立读取。
- “标记”若未来获批，只能新增外部 provenance/状态记录，不得改旧 frontmatter/body/path/ID/links；“归档”若未来获批，只能是可审计的只读边界变化，不能移动或重命名原文件；“迁移”必须另立 Proposal，先 dry-run + manifest + backup/rollback + 显式确认。
- 25 条隔离规则：验证分两面运行——(A) current scope 只扫描本 Proposal/current v3 artifacts，要求无新增错误；(B) historical baseline 固定为本次 validate all 的 25 条路径/目标集合，单独报告、单独计数，不与 A 合并，也不自动修复。后续若历史错误数变化，必须报告 baseline drift，而不是默认为修复成功。
- 任何跨域 link（current → history 或 history → current）只作为 provenance/风险报告，不做 alias、重写或补链；历史 body/path 不变是验收不变量。

## Open Questions

1. 仓库无法证明 ff-wiki-flowforge 中哪些文件确属外部用户历史 wiki；需要用户/产品 owner 确认所有权边界和是否存在未声明的外部引用。
2. 是否需要未来的只读历史展示、搜索或跨域跳转；现有 accepted DEC 仅约束本轮不提供这些能力，不替未来产品决定。
3. “标记”采用何种不改原文件的 provenance/manifest，以及“归档”是否要求永久保留原路径；需另立 DEC/Proposal。
4. 25 条 baseline 的固定载体应否由后续验证命令生成并持久化为 manifest；本轮只记录当前 validator 输出，未创建新基线文件。
5. 未来是否批准历史迁移；若批准，输入范围、重复 ID/旧 link 处理和删除策略仍需用户决定，并强制 dry-run、manifest、backup/rollback、显式确认。
