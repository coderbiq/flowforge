# 当前文档 Agent 部署资产 v2 路由证据

<!-- analysis-mode: complex -->
<!-- analysis-work-id: v2-legacy-audit-r1-W3-current-assets -->

## Summary

为 `W3-current-assets` 提供当前 README/docs/AGENTS/assets/skills 中 v2 actionable 路由、历史说明和部署归属的可复查证据。

## Source

仓库内只读来源：`README.md:1-56`、`AGENTS.md:155-184`、`assets/AGENTS.md:1-38`、`assets/skills/**`；部署映射见 `internal/core/project_manifest.go:81-110`，初始化部署见 `internal/command/assets_deploy.go:15-45,141-189`，同步/冲突语义见 `internal/command/sync.go:97-108,267-325,624-703`，兼容桥见 `internal/command/assets.go:13-25`。未访问外部来源或目标项目。

## Evidence

已完成 README、AGENTS、docs、assets/skills 与 manifest/deploy/sync 实现的逐项复核；以下观察均带有可复查文件与行号。

### Observations

1. 当前入口一致性：`README.md:3,17,24-32,44`、`docs/architecture.md:31`、`docs/cli-design.md:9-20`、`docs/design-skill-workflow.md:18-24`、`docs/index-management.md:29`、`docs/knowledge-system.md:3,26` 及 `docs/proposal-v3/{README.md:22,cli-spec.md:8-22,skill-spec.md:16,implementation-plan.md:16}` 都把 FEATURE/card CLI 作为当前入口，并把旧 task/structure/log/requirement 说明为删除或历史边界；这些旧词在此处是规范性负向说明，不是可执行旧路由。

2. `AGENTS.md:175` 仍写“DEPRECATED”，而同一仓库规范及 `assets/AGENTS.md:22` 已明确“not current routes”。这会让 Agent 误以为仍存在兼容入口；建议改写为“not current routes / do not use”，不能继续使用 deprecated 语义。

3. 部署资产中的 `assets/skills/flowforge-curate/references/workflow-rules.md:32-35` 仍有 `STR-NAME / create` 旧占位模板；它位于部署 reference，Agent 可直接读到，应改为当前 card/link 关系表达。`assets/skills/flowforge-design/references/card-templates.md:123-133` 保留完整 Requirement/Design/Implementation Task/Log “DEPRECATED”空模板；这是部署内容中的旧模型入口，若无兼容读取用途可直接删除该段，否则必须整体标为 historical、明确不可执行。

4. 未标记 `historical` 的仓库文档仍包含可复制执行的 v2 路由：`docs/flowforge-v2-end-to-end-smoke.md:1-4,62-254` 使用 `card create --type finding/requirement/design`、`structure add`、`task create`、`context task`、`log create`；`docs/flowforge-design-skill-draft.md:32,79,87-106,313-346`、`docs/flowforge-design-skill.md:15,55-72,386-388`、`docs/design-skill-cli-contracts.md:33-40,119,195-200,316-401`、`docs/card-architecture-invariants.md:46,84-188`、`docs/cli-design-principles.md:3,38,71,96-99,141`、`docs/ingest-skill-design.md:33,91,334-422,553-610`、`docs/library-knowledge-ingestion-design.md:4,35,126-167,280-291`、`docs/remediation-card-fragmentation.md:51,184,279-285,377` 均存在旧命令/类型/任务模型。它们不是 README 当前入口引用的 v3 权威文档，但因未标历史，仍可被检索误用。

5. 同类但较低风险的残留包括 `docs/development.md:3` 的 `v2.0.0-alpha` 元数据、`docs/business-layer-outline.md:361,479-480` 与 `docs/business-layer-reference-index.md:33-34,100` 的 TASK/旧 backup 路径，以及 `docs/flowforge-design-skill-draft.md:138,179-184` 的 v2 walkthrough 引用；应标为 historical 或改写，不应作为当前设计入口。明确已标历史的 `docs/v1-analysis.md:1-3`、`docs/references/cli-best-practices.md:1-3` 等不属于本次清理对象。

6. 部署归属是确定的：`project_manifest.go:81-110` 将 `assets/skills` 部署到目标 `.agents/skills`，`assets/AGENTS.md` 作为目标 `AGENTS.md` 的 managed block；`assets/templates` 与 `assets/wiki` 也进入 manifest（当前 wiki 仅 `.gitkeep`）。根 `AGENTS.md`、`README.md`、`docs/**` 不由 manifest 下发。初始化部署当前调用 `copyDir(..., false)`（`assets_deploy.go:22-27,175-189`），用户同路径文件冲突时保留并报告；上一 Proposal FIND 中关于此处 `overwrite=true` 的观察已被当前工作树修正，不构成现状风险。

7. 同步路径默认 dry-run/manifest conflict/preserved，`--adopt` 才替换已知受管文件（`sync.go:97-108,306-325`）；AGENTS FLOWFORGE block 另有 preserved 语义（`sync.go:624-703`）。隐藏 `assets update`（`assets.go:13-25`）是 v3.1.x 自更新兼容桥，不是 Agent 当前路由；其保留截止版本/升级窗口仍未知。

### Inferences

- 可直接清理候选：部署 reference 的 `card-templates.md:123-133` 旧模板（确认没有历史读取/教学用途后）；`curate/workflow-rules.md:34` 的 `STR-NAME / create` 占位；`AGENTS.md:175` 的 deprecated 表述应直接改为不可用语义。
- 需改写或显式标记 historical：上述未标历史的 v2 文档群，尤其 v2 Smoke 和两份 design SKILL 草案；若保留原始记录，不应只替换单个词，而要在文件头加历史声明并阻止其作为当前入口。`README.md:44` 的“其余 v2 文档仅作 historical”目前与这些文件缺少标记相矛盾。
- 部署风险集中在 `assets/**`：删除/改写会进入目标项目的 `.agents/skills` 或 `AGENTS.md`，应先用 `sync --dry-run`、默认 sync 检查 conflict/preserved，再由明确授权决定 `--adopt`；本 FIND 不授权接管目标文件。

### Unknowns

- `assets/skills/flowforge-design/references/card-templates.md` 的 deprecated 模板是否被任何外部部署流程作为只读迁移说明依赖，仓库内无引用证据。
- 隐藏 `assets update` 兼容桥的最后受支持旧客户端版本/截止 release 未在 brief 或代码中定义。

## Impact

直接删除/清理只应限于已确认无历史读取责任的部署旧模板和占位语句；未标 historical 的 v2 文档应先改写为 v3 或加历史标记。误删 assets 会改变嵌入 manifest 并传播到目标项目，误用 `--adopt` 可能替换用户修改；默认 sync 的 conflict/preserved 和 dry-run 是最低验证门槛。旧客户端兼容桥的移除需要独立版本/迁移决策。
