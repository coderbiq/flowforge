# UI prototype

Build several materially different visual approaches on one throwaway route. Select variants with a URL parameter and a small floating switcher so reviewers can compare the same content and state.

Keep behavior and fixture data constant across variants. Vary information hierarchy, interaction structure, density, and visual language—not just colors. Record the winning and rejected qualities in the calling design authority; do not retain the prototype as production implementation.

Completion means reviewers can name which approach best supports the target task and why.
