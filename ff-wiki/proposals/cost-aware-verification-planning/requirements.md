# 成本感知的规划：连续实现、集中验证

<a id="purpose"></a>
## 目的与事实

让 Plan 以实施总成本组织工作：先连续完成一个完整逻辑，再集中验证与独立审查，减少碎片化验收和实施者、验证者、主会话之间的往返。避免重复运行只是次要收益；每个检查即使只执行一次，过密的关口仍可能让交付变慢。需求、设计、Plan、Refine 的职责保留。

用户在本 proposal 暂停后明确了上述本意，并授权按[成因研究](../../research/2026-11-05-plan-verification-handoff-causal-analysis.md)调整 proposal、重新规划，必要时回滚。来源分类见[来源归类](source-notes.md)。01已采用组末验证仍出现返工，故不能把问题仅归于票数、重复测试或模型推理强度。复盘超时受电脑休眠影响，不作效率依据。

<a id="reliability"></a>
## R1：可靠性边界不变

- 轻量实施者按合同机械执行，不自主设计、选测、豁免失败、改变验收或修改预设测试。
- 保留 Plan/Refine、测试作者与实施者分离、独立 Round 0、Standards/Spec 双轴及真实缺陷阻塞。
- 不因时间、轮数或Low标签强制通过；不以full mode、模型升级或降低thinking代替流程优化。
- 用户本轮授权重规划；发布新规划不等于未完成产品已经验收，不恢复旧02运行继续执行过期合同。

<a id="allocation"></a>
## R2：按完整逻辑组织交付

Plan 先确定可连续实现的完整行为，再决定是否拆票。可独立验证不等于值得独立成票；切分必须有独立交付、真实依赖、风险隔离或上下文容量理由，并考虑新增准备、交接和收口成本。关联接口、实现、调用方和错误处理可以是同一票内的多个步骤，不自动成为多个验收关口。

本轮不引入多票共享关闭状态。一票应能证明自己承诺的行为；跨票组合确有独立观察条件时，才安排普通阶段验收票。局部通过不冒称整体通过；发布/真实使用前仍须适用的正向证明。

<a id="cost"></a>
## R3：成本优先约束关口与交接

新计划默认连续完成逻辑后集中验证。新增中途验证关口应说明它解决的具体未决假设、避免的重大返工或保护的使用边界；不能因为完成了一个Change就自然追加验收。

成本包括准备、上下文重建、角色交接、模型处理、工具运行、证据维护和返工。只需在实际取舍处给简短理由，不增加评分、精确预算、独立成本模板或逐命令人工账本。无测量值写未知。

<a id="groups"></a>
## R4：实施步骤与验证时机分开

Plan 必须给新票明确的连续实现范围和检查时机，默认一个完整逻辑组完成后统一运行其检查。提前检查是有理由的例外，不把验证完整性变成每步即时验证。

执行者依照明确安排，不对组内计划中的半完成状态运行未安排的验收，不自行调整检查。实际越界、合同冲突或指定检查失败仍按原边界停止。预设测试可以提前准备；准备测试不等于在每个实现步骤后交给验证者。

<a id="fix"></a>
## R5：按影响范围合批修复

Review 汇集同一固定点上可确认的问题，发布机械可执行的Fix批次及匹配检查。没有新差分影响或新证据时，不重新打开已裁决事项；新真实缺陷仍处理。改变责任、接口、验收、写集等仍走原design return/repair，不借优化绕过。

普通小Fix不重复发明整票验证策略；可引用已明确且仍适用的安排。新检查及历史复用仍由权威决定、独立审查确认，实施者不自判。

<a id="evidence"></a>
## R6：保留真实证据，减少重复表达

原始运行、失败、实际差分和历史归属必须可追溯；旧结果不得冒充本轮执行。一次实跑可覆盖多个Change，但不能记成多次。

重复叙述不是新增证据。Refine核实合同事实，实施者只需证明本轮动作/关键约束已正确理解，不强制多份全文复述。已核实且未变化的事实可准确引用；已有四元组和五节诊断兼容保留。本轮不改Schema或证据解析算法。

<a id="review"></a>
## R7：职责分离不等于每个动作都新开代理

只读审查子代理执行明确的Round 0或指定轴，返回有依据的发现；不能被要求写票、关闭票或再派子代理。主会话承担工作流编排、权威裁决和已裁决结果的写回，不为短小机械回填额外启动角色。

保留一票一新执行上下文及独立审查。新上下文读取当前票、必要权威和相关证据，不默认重新处理整个会话历史。没有新决策问题时不重复分析已确定事项。完整工作流owner与仅做一项只读核查的入口必须明确区分。

<a id="compatibility"></a>
## R8：新计划默认改善，旧合同显式迁移

新Plan默认发布紧凑的集中验证安排；旧票没有该安排时继续旧规则。迁移旧票由权威修改，不由执行者临场解释。源码、嵌入、实际部署规则必须区分；待修改文本不能被默认为当前执行约束。

不改CLI签名、Issue Schema、状态机或模型配置，不重写GIIS中的执行中proposal。先前完成的真实安全修复及审查历史保留；新目标的交付另行证明。

<a id="measurement"></a>
## R9：验证计划行为与总成本，不承诺提速比例

对固定输入观察：是否组织完整逻辑、关口是否有必要性、实施是否按组连续完成、是否减少无新信息的角色交接、修复是否只重开受影响范围，以及可靠性是否保持。

使用已有轨迹观察实际交接、验证关口、Fix批次、遗漏和重开；时间区分墙上跨度、活跃区间、等待与休眠，父子并行不得相加。没有同类对照就不能声称净提速。受控行为通过只证明规则遵从，不等于生产收益。

<a id="test-authority"></a>
## R10：既有受限测试作者入口继续有效

R10语义与revision 2保持一致：主会话向实际Plan/Refine会话实例签发指定项目、短期、精确测试文件授权；角色自称或提示词不产生权限。越界、符号链接、缺失/无效授权继续拒绝，不关闭保护、不通过shell绕过、不声称OS沙箱。

00/03已经交付并独立审查的入口和边界修复保留。新规则相关测试仍由合法作者准备并验证后冻结，再交给独立实施者。未改变授权产品路径时，不为本次规划重跑全部native握手或安全矩阵。

<a id="scenarios"></a>
## 必须覆盖的行为

- 普通关联修改：Plan组织完整逻辑，默认集中检查；实施者组内不插入小验收或角色交接。
- 高风险前置：确有关键假设/不可逆使用时保留必要检查，不把“后置”变成所有测试都拖到最后。
- 小Fix与失效证据：有效旧证据可独立确认复用；共享输入变化或版本不明时扩大/阻塞，不凭旧通过放行。
- 角色、兼容与发布：只读角色不写票/再派发；旧票未迁移走旧规则，新安排残缺先返回；发布缺适用正向证明仍被阻止。

这些是覆盖义务，不要求每个分支都另开一套模型会话；由设计分配到现有自动测试、独立语义审查或少量真实链路。

<a id="scope"></a>
## 范围

本轮调整Plan选票原则、检查时机默认、Refine/实施复述、Review批次与范围、角色提示和主会话写回职责，并验证一致部署。证据复用和局部/阶段门禁保留必要内核，取消以大量说明和重复取证证明节省的做法。排除权限放宽、取消独立审查、自动缓存/调度平台、批量迁移其他项目及模型强弱评测。
